Definition of done for every milestone

  1. Architecture and boundaries documented before implementation.
  2. Production-quality code with type hints, docstrings and explicit error handling.
  3. Unit, failure-path and relevant integration tests.
  4. Compilation, tests, coverage, audits and release-gate checks pass.
  5. README, STATUS, CHANGELOG, milestone documentation and ADRs updated where applicable.
  6. Repository is clean; changes are committed, tagged and pushed.
  7. No milestone is complete merely because code exists; behavior, diagnostics and maintenance workflow must be verified.
